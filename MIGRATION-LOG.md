## Node 24

- Production runs Node 24 (`node:24-slim`, V8 13.6), and this machine has Node 22 (V8 12.4). Vectors from slice 2b on are generated with an official Node 24.22.1 build (checksum-verified, at `/tmp/node24`). Regenerating every earlier package under Node 24 changed four vector files: audio-assets (`Math.pow`, 25 results), puzzle-assets (`Math.pow`, 16, and the colour contrast picks built on it), icon-order-assets (inputs built with `**`; its Rust still passes) and web-bot-auth (WHATWG URL serialisation: `foo:/x` now gives `foo:///x`). So the first three ports were proven against Node 22, not production, and audio-assets, puzzle-assets and web-bot-auth fail against Node 24. Each is fixed in its own commit after this line, or is BLOCKED below.
- V8 13.6's `Math.pow`, measured over 200,000 inputs: `NaN` for a `NaN` exponent and for `|x| == 1` with an infinite exponent, `x * x` when `y == 2`, and otherwise the system libm `pow` (the node binary links glibc's `libm.so.6`). The earlier ports transcribed V8 12.4's fdlibm `pow`.
- Deployment consequence: a Rust port that matches `Math.pow` has to call the same glibc libm as the Node image, so the Rust provider image must be glibc-based (Debian bookworm, like `node:24-slim`), not musl or a static build.

## versioning

- Rust crates: 6.0.0, done. npm: no Rust-backed artifact exists yet, so nothing to version as `6.0.0-rust.N` today.
- Moving the plain JS line to 6.0.0 is left for the release owner. The packages are on mixed versions today (logger 2.1.4, dotenv 3.0.61, provider 5.19.2, cli 3.8.33), and a changeset can only bump by a level (a "major" turns 3.0.61 into 4.0.0), so landing every package on exactly 6.0.0 means setting the versions by hand at release time. The changesets on this branch stay `patch` because the TS is unchanged.
- To settle before the first `6.0.0-rust.N` publish (not blocking any port yet): (a) under semver, `6.0.0-rust.N` sorts *below* `6.0.0`, and a range like `^6.0.0-rust.3` also matches a later plain-JS `6.0.1`, so anyone depending on the Rust-backed artifact must pin an exact version or they silently get the JS one; (b) changesets' prerelease mode applies to the whole repo, so the `-rust.N` line cannot be versioned by changesets from the same branch as the plain 6.0.0 line, and needs its own version step; (c) it must be published under its own dist-tag so `latest` stays on the JS line.
